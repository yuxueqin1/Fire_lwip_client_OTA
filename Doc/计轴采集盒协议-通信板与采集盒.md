# 计轴采集盒（0x50 / WBTQ301JH-1B3）通信协议说明书

> **本文档用途**：作为"计轴模拟器"开发的协议依据。模拟器模拟的是**采集盒（从机）**侧。
> 通信板（主机）侧逻辑已经写死，模拟器必须完全遵守下列格式才能被通信板识别。
>
> 依据：`User/main.c`（`uart_axle_counter_module_exchange` / `uart_axle_counter_online` /
> `uart_axle_counter_upload_pulse` / `uart_process_axle_counter`）与 `User/usart/bsp_rs485.c`
> （`uart_custom_send_adjust_time`）。

---

## 1. 总体架构

- **通信板 = 唯一的 485 主机（Master）**，主动发起所有帧。
- **采集盒 = 从机（Slave）**，只应答，绝不主动上报。
- 通信板按轮询周期依次查询每个从机地址，采集盒的**实时数据**和**脉冲曲线数据**都通过同一条 0x03 应答帧带回来，**没有单独的曲线查询指令**。

---

## 2. 物理层参数

| 项目 | 值 |
|---|---|
| 接口 | RS485 半双工 |
| 波特率 | 配置码 1=9600、2=19200、3=38400、4=57600，默认 19200 |
| 数据格式 | 8 数据位，无校验，1 停止位（8N1） |
| CRC | **Modbus CRC16**（多项式 0xA001，初值 0xFFFF），**低字节先发** |
| 字节序 | 板↔盒 帧内所有多字节字段一律 **大端（Big-Endian）**，与板→上位机的帧（小端）相反 |

**时序约束（通信板侧，模拟器不强制但要知道）**：
- 发送请求后首字节超时 100ms，字节间间隔超时 50ms；
- `rx_len < 5` 或 CRC 错误即判离线，连续 3 次失败才真正把该模块置离线（清除 link_mask 位）；
- 轮询周期 ≈ `900ms − 25ms × 从机数`。

---

## 3. 通信板 → 采集盒（共 2 条指令）

### 3.1 校时命令（0x10，共 13 字节）

板在 `changetime` 置位时对每个模块发送一次，把 4 字节 Unix 时间戳写入从机寄存器 0x0000~0x0001。**板不等应答。**

```
[从机地址(1)][0x10][0x00][0x00][0x00][0x02][0x04][时间戳(4B,大端)][CRC低][CRC高]
```

| 偏移 | 字节 | 含义 |
|---|---|---|
| 0 | addr | 从机地址 |
| 1 | 0x10 | 功能码：写多个寄存器 |
| 2-3 | 0x00 0x00 | 起始寄存器地址 = 0x0000 |
| 4-5 | 0x00 0x02 | 寄存器数量 = 2 |
| 6 | 0x04 | 数据字节数 = 4 |
| 7-10 | 时间 | Unix 秒，大端（如 `6A 8F B0 04`） |
| 11-12 | CRC16 | 低字节在前 |

**模拟器行为**：收到后把内部虚拟时钟设为该时间，之后按实时时间递增；可以不应答（板不接收）。

### 3.2 实时查询（0x03，共 8 字节）

每个轮询周期对每个从机发送：

```
[从机地址(1)][0x03][通讯确认码高][通讯确认码低][脉冲个数高][脉冲个数低][CRC低][CRC高]
```

| 偏移 | 字节 | 含义 |
|---|---|---|
| 0 | addr | 从机地址 |
| 1 | 0x03 | 功能码：读寄存器（实际读全表） |
| 2-3 | **通讯确认码** | 上次应答中读到的 reg12 的值（采集盒一直累加），原样带回做水位 ACK；首次为 `0x0000`（见第 5 节） |
| 4-5 | **要读取的脉冲个数** | `0x0000` = 普通查询/不确定有没有脉冲；当上次应答 reg13 非 0 时，填剩余未读脉冲数 N，采集盒才会下发脉冲块 |
| 6-7 | CRC16 | 低字节在前 |

## 4. 采集盒 → 通信板（0x03 应答帧）

### ⚠️ 最重要的格式特点：应答帧没有字节长度字段（无 byte_count）

```
[从机地址(1)][0x03][寄存器数据(28B)][脉冲块(可选)][CRC低][CRC高]
```

- 寄存器数据从**偏移 2** 开始（不是偏移 3，因为无长度字段）。
- 帧尾 2 字节是 CRC，覆盖除 CRC 外的全部字节。
- `rx_len >= 24` 即认为实时数据有效；脉冲块长度 = `rx_len − 32`（2B 头 + 28B 寄存器 + 2B CRC）。

### 4.1 寄存器表（大端，每寄存器 2 字节）

| 寄存器 | 应答偏移 | 内容 | 通信板用途 |
|---|---|---|---|
| reg0 | 2-3 | 保留 / 模块状态 | 仅上传上位机 |
| reg1 | 4-5 | **KGL 报警寄存器** | 低 6 位 `(val & 0x3F) == 0` → 报警；非 0 → 正常 |
| reg2-3 | 6-9 | **本组曲线开始时间 Unix 秒（4B 大端）** | 用作脉冲时间偏移的基准 |
| reg4-10 | 10-23 | 其他实时值 | 仅上传上位机 |
| reg11 | 24-25 | **本组曲线开始时间 Unix 毫秒** | 同上 |
| reg12 | 26-27 | **通讯确认码** | 一直累加的序号，采集盒每条应答都递增；通信板总是把最新值原样带回做水位 ACK |
| reg13 | 28-29 | **剩余未读脉冲数** | 读取请求的应答里 = 尚未读走的脉冲数；**只有请求帧第5-6字节>0 时该应答才附脉冲块** |

> 通信板把 **reg0~reg9（前 10 个寄存器，20 字节）** 当作"实时值"，字节交换（大端→小端）后上传上位机。

### 4.2 脉冲块（仅当请求帧第5-6字节>0 即"读取请求"时出现，位于偏移 30 之后）

- 普通状态查询（请求第5-6字节 = 0）的应答**不带脉冲块**，只回实时值 + reg13 报告剩余未读数。
- 读取请求（请求第5-6字节 = N）的应答才会附上最多 N 个脉冲的脉冲块。

```
[本包上报脉冲个数(2B,大端)]
┌ 每个脉冲 ───────────────────────────────┐
│ [脉冲时间Unix秒(4B,大端)][毫秒(2B,大端)]  │
│ [通道号(1B)][采样点数n(1B)][采集值n×1B]  │
└────────────────────────────────────────┘
```

| 字段 | 长度 | 说明 |
|---|---|---|
| 脉冲个数 | 2B 大端 | 本包共有几个脉冲 |
| 时间秒 | 4B 大端 | 该脉冲发生时刻 Unix 秒 |
| 时间毫秒 | 2B 大端 | 该脉冲发生时刻毫秒 |
| 通道号 | 1B | 采集通道编号 |
| 采样点数 n | 1B | 该脉冲的采样点数量 |
| 采集值 ×n | n×1B | 电压采样值，单位 0.1V |

**"曲线"在这里就是每个脉冲的采样值序列**（轴的脉冲波形）。曲线是跟着 0x03 应答的脉冲块一起回来的，没有单独的曲线查询。

### 4.3 完整应答帧示例（读取请求第5-6字节=2 的应答，从机地址 01）

```
01 03
00 00          reg0
00 3F          reg1  KGL 正常 (低6位=0x3F)
6A 8F B0 04    reg2-3 曲线开始秒 = 2026-08-27 03:33:24
00 00 00 00 00 00 00 00 00 00 00 00   reg4-9
00 00          reg10
03 E8          reg11 曲线开始毫秒 = 1000
00 01          reg12 通讯确认码 = 1
00 02          reg13 未读脉冲数 = 2
00 02          脉冲块: 本包2个脉冲
6A 8F B0 04 03 E8 01 04  脉冲1: 秒+毫秒(1000)+通道01+采样点4
0C 0C 0A 08              脉冲1 采集值 ×4
6A 8F B0 05 00 FA 02 03  脉冲2: 秒+毫秒(250)+通道02+采样点3
0F 0D 0A                 脉冲2 采集值 ×3
XX XX                    帧尾 CRC16（低字节在前）
```

## 5. 读取脉冲的两步流程 + 通讯确认码水位 ACK（模拟器必须实现的状态机）

读取脉冲不是一步完成的，而是"先报告、后读取"两步：

**第一步（状态查询）**：请求帧第 5-6 字节 = `0x0000`（不确定/不读取）。
采集盒应答：只回实时值 + reg12（新的累加确认码）+ reg13（剩余未读脉冲数），**不带脉冲块**。

**第二步（读取请求）**：通信板看到 reg13 ≠ 0 → 下一次请求帧第 5-6 字节填该数 N。
采集盒应答：实时值 + reg12 + reg13（交付 N 个后**剩余**的未读数）+ **最多 N 个脉冲的脉冲块**。

之后按 reg13 循环第二步，直到 reg13 = 0 恢复普通查询。

**通讯确认码（reg12）= 一直累加的序号**：
- 采集盒**每条应答都递增** reg12（无论有没有脉冲），通信板**总是**把最新读到的值原样填回下一次请求帧的第 3-4 字节（reg13=0 时**不会**清零）。
- 采集盒靠这个回显值判断"通信板已收到到哪一帧"：当回显值 ≥ 某批脉冲所在应答的确认码时，该批脉冲可确认清除。这是滑动窗口水位 ACK。

**采集盒侧状态机**：

1. 收到新脉冲 → 入"待确认队列"（记录入队时的序号）。
2. 收到请求 → **先按回显码 C 出队**（清除所有"已发出且序号 ≤ C"的脉冲），再：
   - 请求第 5-6 字节 = N（>0）→ 从队首取最多 N 个脉冲放进应答的脉冲块；reg13 = **出队后队列剩余数（含本批刚下发、尚未被回显确认的）**；reg12 递增。
   - 请求第 5-6 字节 = 0 → 只回实时值；reg13 = 队列长度；reg12 递增；**不带脉冲块**。
3. 收到请求里的回显码 C → 清除所有"已发出且序号 ≤ C"的脉冲（即通信板已确认收到）。

> 要点：**在回显码确认前，采集盒不能丢弃已发出的脉冲**（否则 CRC 错误/超时丢帧时数据就丢了）。模拟器建议维护一个"待确认队列"，按回显序号出队。
>
> ⚠️ **因此 reg13 存在"滞后一轮"的现象**：交付了脉冲的那一条应答里，reg13 **不等于**交付后的真实剩余（本批还没被回显确认），要等通信板下一次请求把回显码带回来后，reg13 才会降到 0。**所以"reg13=0"不能用作"本批就是最后一包"的判据**——那一轮已经不含脉冲块、不会再发 0x09 帧了（详见第 6 节结束标志）。

**一个完整的读取循环**：

| 周期 | 通信板→采集盒 | 采集盒应答 | 通信板处理 |
|---|---|---|---|
| A | `[addr,03,cc=0,count=0]`（不确定） | reg12=C1, reg13=5，**无脉冲块** | 存 cc=C1；待读个数=5 |
| B | `[addr,03,cc=C1,count=5]`（读5个） | reg12=C2, **reg13=5**（本批尚未回显确认），**含5个脉冲块** | 存 cc=C2；5 个脉冲按通道合并成若干 0x09 帧（如 ch1 一帧 3 个、ch2 一帧 2 个），**各帧结束标志均=1（板上传固定置1）**；待读个数=5 |
| C | `[addr,03,cc=C2,count=5]`（回显 C2 清队列） | reg12=C3, reg13=0，**无脉冲块**（队列已空） | 存 cc=C3；待读个数=0，本轮无 0x09 帧 |

> **关于"一次读 N 回几个"**：请求第5-6字节=N 时，采集盒从队首取**最多 N 个**脉冲放进应答，reg13 = 队列剩余数。正常情况下队列里有几个就回几个（如上例：问 5 回 5，reg13=0）。只有当一帧装不下（脉冲多、采样点多导致应答帧超过采集盒最大帧长）时，采集盒才会**分批**回：每轮只装得下的那些，reg13 报剩下的，通信板按 reg13 循环继续读，直到 reg13=0。结束标志由板上传**固定置 1**（见第 6 节），上位机按"每包即一条完整曲线"渲染。

## 6. 板上传上位机帧（了解即可，模拟器不需要生成）

通信板把采集盒数据再组包上传上位机，用于理解时间基准：

**实时帧（帧标志 0x01）**：
```
[端口号(1)][主协议(1)][子协议(1)][0x01][分机号(1)][长度(2B,LE)][link_mask(4B,LE)][各模块实时值]
```
每模块 20 字节，由应答中的 reg0~9 **大端转小端**后顺序拼接。

**脉冲帧（帧标志 0x09）**，**按通道分组**（协议 Table 1.4）：采集盒一包内可能混多个通道，通信板把同一通道的全部脉冲合并进同一个 0x09 帧（N = 该通道脉冲数），不同通道拆成多个帧：
```
[设备ID(1)=从机地址][通道号(1)][时间戳(4B,LE)][时间戳毫秒(2B,LE)][结束标志(1)][当前包脉冲数(2B,LE)=N]
[脉冲1: 点偏移(2B,LE)][包含点数(1B)=n][采集值×n]
...
[脉冲N: 点偏移(2B,LE)][包含点数(1B)=k][采集值×k]
```
其中：
```
点偏移 = ((脉冲时间秒 − 本通道最早脉冲秒)×1000 + (脉冲毫秒 − 本通道最早脉冲毫秒)) / 4
```
- **按通道拆帧（不做跨通道组包）**：通信板每收到一包脉冲块就立即上传，按通道分组，每出现一个通道发 **1 个 0x09 帧**；同一通道的脉冲合并进同一帧，帧头通道号 = 该通道号，N = 该通道在本包中的脉冲数。一包混几个通道就发几个帧。
- **头部时间戳 = 本通道最早脉冲的秒/毫秒**：每个脉冲在脉冲块里自带 4B 秒 + 2B 毫秒，取**本通道最早者**作为帧头时间戳（大端转小端），同通道其余脉冲的点偏移相对它计算（单位 4ms）。基准取的是本通道最早脉冲，故点偏移恒 ≥ 0，不会出现负偏移回绕。
- **结束标志**：**每个通道帧都带上**，板上传**固定置 `1`**（曲线采集结束）。

  > **⚠ 不再按 reg13 判断**（原判据已作废）：计轴是**连续采集的活传感器**，读取期间仍有新脉冲持续入队，采集盒回的 **reg13（剩余未读脉冲数）基本不会等于本包实发数**。原判据（`reg13 == 0` 或 `reg13 == 本包实发数`）于是几乎恒判为"未结束"（0），而**上位机只展示结束标志 = 1 的曲线** → 首包及后续包全部不显示。上位机按"每包即一条完整曲线"渲染，故每包统一置 1。
  >
  > （历史判据：曾用 `本批实发数 == reg13` 判"最后一包"，理论依据是 `reg13 = 本批实发数 + 尚未下发的剩余数`，两者相等即剩余数为 0；但在活传感器下剩余数几乎不为 0，该判据在实机上不可用。低频那版则直接在帧内写死 1。）

## 7. 模拟器实现清单

1. 监听 485，收到帧 → 校验地址和 CRC（Modbus CRC16，低字节先发）。
2. 功能码 `0x10` → 更新内部时钟（可不应答）。
3. 功能码 `0x03` → 按第 4 节格式回帧；**只有请求第 5-6 字节 > 0（读取请求）时才带脉冲块**，走第 5 节两步流程 + 水位 ACK。
4. 实时值（reg0-9）、KGL（reg1，正常置非 0）、曲线开始时间（reg2-3+reg11）、通讯确认码（reg12，**一直累加**）、剩余未读脉冲数（reg13）全部**大端**。
5. **应答里没有长度字段**，寄存器从偏移 2 开始，帧尾是 CRC16（低字节在前）。
6. 可配置功能：产生/注入脉冲（reg13 显示剩余数，收到读取请求后附脉冲块）、模拟报警（reg1 低 6 位清 0）、模拟离线（不应答）。
